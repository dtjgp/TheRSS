## Referenced Sites

### Beautiful UI

- URL: <https://www.beautifului.dev/>
- Current catalog emphasizes AI-native interface primitives: Loading State, Thinking, Streaming
  Text, Approval Card, Tool Chips, Task Rows, Prompt Bar, Context Cards, Filter Table, Sidebar Nav,
  Search, and Insight Cards.
- Strong TheRSS fit: Task Rows and Context Cards make asynchronous state and provenance legible
  without turning the screen into chat.
- Rejected: Chat, recommendation confidence, diff-table approval, and tool-call chrome are not part
  of the Discover contract.

### beUI

- URLs: <https://beui.dev/> and <https://beui.dev/components/blocks/command-palette>
- Current catalog advertises 111 React 19/Tailwind 4 components. Relevant entries include Agent
  Activity, Agent Loading States, Command Palette, Tabs, Tooltip, Bouncy Accordion, Animated Toast
  Stack, and Expandable Action Bar.
- Strong TheRSS fit: compact active-row/state treatment and explicit keyboard/reduced-motion intent.
- Boundary: examples are built around Motion, Tailwind, and the shadcn registry. Adding those layers
  would be disproportionate because TheRSS already has React, semantic CSS, Command-F, native menus,
  and accessible split panes.

### Rare UI

- URLs: <https://www.rareui.com/> and <https://www.rareui.com/components>
- Current catalog has 14+ single-file animated components across display, AI kit, navigation,
  inputs, and feedback. Examples include Fluid Orb, Gravity Letters, Grid Reveal, Bounce Sidebar,
  Proximity Sidebar, and Emoji Reaction.
- Decision: do not adopt. The catalog is optimized for novelty and visual signature; none of the
  reviewed patterns solves a higher-priority Discover scanning, evidence, or progress problem.

### Transitions.dev

- URLs: <https://transitions.dev/> and <https://transitions.dev/skill.html>
- Current catalog contains card resize, text-state swap, skeleton-to-content reveal, tabs sliding,
  success/error state, thinking state, and streaming transitions. Its skill page also exposes
  review/refine/polish workflows and 27+ recipes.
- Strong TheRSS fit: restrained status swaps and compositor-friendly opacity/transform transitions,
  with the existing global reduced-motion override remaining authoritative.
- Boundary: no skill or premium/free recipe bundle is installed. The task needs one small state
  transition, not a new workflow dependency.

### shadcn/ui

- URLs: <https://ui.shadcn.com/> and <https://ui.shadcn.com/docs/components>
- Current catalog covers foundational open-code primitives including Item, Progress, Collapsible,
  Resizable, Scroll Area, Command, Kbd, Tabs, Tooltip, Skeleton, and Sidebar.
- Strong TheRSS fit: composition and accessible state contracts. TheRSS already has equivalent
  project-native primitives and should keep owning their code rather than importing a second design
  system.

## Current TheRSS Baseline

- Strengths: coherent Apple semantic tokens, system accent support, dark/forced-color/reduced-motion
  handling, accessible resizable sidebar and list-detail panes, keyboard selection, collapsed search
  details, and explicit evidence boundaries.
- Current gap: an active search across up to 22 sources is represented by one spinner plus one line
  (`x of y sources finished`). It does not expose the already-real three-stage mental model: validate
  plan, search selected sources independently, then assemble the persisted ranked session.
- Current terminal state: the collapsed Search details disclosure is truthful but reads as one badge
  plus generic copy; the same three-stage model is not visible after completion.
- Rejected broader redesign: replacing the native sidebar, list-detail workspace, form, typography,
  or selection geometry would discard recently verified behavior without solving a demonstrated
  task problem.

## Evidence Boundaries

- Public UI examples can establish observable layout and interaction patterns, not their internal
  implementation, accessibility quality, conversion impact, or suitability for TheRSS.
- Any adopted pattern must be re-derived from TheRSS's own product model, content density,
  provenance requirements, and desktop interaction contract.

## Candidate Decisions

- Selected slice: a project-native Discover run pipeline used during an active search, plus a compact
  terminal stage summary inside Search details.
- State model: `Plan query` -> `Search N sources` -> `Assemble session`; state labels remain waiting,
  current, complete, attention, or stopped and are never inferred beyond existing progress/snapshot
  evidence.
- Visual direction: quiet editorial/native utility — semantic text, one system-accent progress track,
  compact status glyphs, no glass hero, orb, 3D effect, confetti, or novelty motion.
- Dependency decision: zero new dependencies and no copied registry source.
