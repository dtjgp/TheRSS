# TheRSS 来源、收藏快照与质量评估契约

## Feature Intake

- 用户要求按上一轮建议继续：来源稳定性、检索/分析质量评估、收藏快照更新与 GitHub 草稿说明。PR #49 标题正文已同步并读回核对，仍为草稿。
- 已观察问题：NBER 的 RSS 无日期，详情页曾返回 403；NCPSD 的 7 条记录只给期号，不能把期号当月份；Saved 更新已有较新检索快照需要取消收藏再保存；单个真实用例不足以评价检索质量。
- 产品目标：更可靠地发现和保留有证据边界的研究线索。保持单用户、本地 SQLite、确定性排序和共享执行端契约。
- 选择：优先使用官方数据与已有本地快照；不引入登录、后台服务、付费 API 或新依赖。仅当官方字段足以核验日期/身份时采用来源替代路径。
- 成本上限：本轮来源诊断每个候选入口先请求一次，再按已证明的修复定点复测；质量基线采用 3 个公开研究问题、2 个已有 CLI，最多 6 次规划和 4 次分析。失败先诊断，不盲目重试。自动化测试全部离线。
- 停止条件：功能及边界回归通过，真实基线及限制可复核，安装/推送/CI 完成。外部缺失日期/403 保留显式降级，不伪造完整数据。独立人工验收保持待真实使用者填写；VoiceOver、付费 API、正式发行暂缓。

## Capability Contract

### Q1 来源稳定性

先检查现有官方 RSS/页面的真实字段，诊断格式拒绝与网络失败。使用官方可核验元数据的改进必须保持来源 ID、文章身份和日期证据。不得把期号转换成月份、把缺少日期转换成今天，或绕过访问控制。为拒绝提供可定位原因，保留已有缓存。

定点诊断：NBER 官方文章仍为 403，已知编号的 Crossref 候选为 404，不采用该备选。NCPSD 列表及一个期号条目的官方详情可读，但缺少可接受的完整出版日期。保留期号记录的日期拒绝；不新增不可靠的数据源。

月份精度修复采用现有 NCPSD 元数据（来源 ID、规范化年月摘要和存储的月初排序锚点）推导，只用于这个已有源的受约束记录；不新增数据库迁移。界面/论文分析显示年月并注明缺日，排序不授予按天的新鲜度奖励；30 天来源窗口按月区间重叠纳入，并明确日期可能不完整。来源哈希保留月份精度，使旧的伪精确日期分析被标为过时。论文提示版本更新且旧 L1 版本仍能阅读。

同时复用固定 HTTPS 同源的重定向检查，应用于 dated-feed 详情请求；验证 XML 结构与日历日期，拒绝错误页面/无效日期。NBER 明确的 401/403 会停止同批次尚未开始的详情请求，保留来源失败说明。离线回归覆盖这些行为，不依靠反复请求失败站点取得全绿。

后续全量检查中 CNBC 镜像再次超时。上游 RSSHub 代码指向官方 `search.cnbc.com/rs/search/combinedcms/view.xml?partnerId=wrss01&id=100003114`，实测 HTTP 200、30 条、约 0.36 秒。采用该同一 Top News 频道的官方摘要 RSS，保持数字 GUID（真实本地 29 条均非 URL 身份），保留原先排除 `/select/` 内容的规则。日期、标题和官方摘要不冒充全文；不再请求镜像的逐篇全文补充。

### Q2 更新收藏快照

Saved 为已收藏记录提供一个明确的更新入口：查找同一来源/同一记录已检索到的最新本地快照，核对其是否更新并应用。无网络、模型或外部写入。没有较新快照时明确无变化；旧版本不可覆盖较新来源；已取消收藏/缺失记录不得静默恢复收藏。

保留收藏状态、原始保存时间和所有历史检索/分析；更新正文/来源与匹配说明后，旧分析按来源哈希自然变为过时。原生 AppKit 和 Web 回退共用 schema 验证的窗口 API，不在 UI 复制存储规则。优先无 SQLite schema 迁移；有必要变化时先补充契约。

### Q3 有界质量基线

使用公开问题，覆盖模型压缩、计算能效、电力需求响应；保存执行器、问题、规划提示版本/输入哈希、计划、来源状态、耗时、规范化结果及排名。评估器核验重复、目标类型、日期/来源一致性，并提供 Top-10 相关性标注清单与计算接口。

规则命中率、助手辅助标注和人工参考标签分别记录。没有真实人工标签时不输出“人工准确率”或召回率；有限候选集不能代表全网相关论文总量。对 4 次公开条目的分析核对来源主张、推断与未知项，保留错误及未解决项。普通用户日常运行不自动触发评估或收费调用。

## Uncertainty Reducer

- Q1：官方响应的有界只读样本；Q2：SQLite 行、保存/分析哈希及当前 native Saved 控制器的回归原型；Q3：真实业务服务加隔离测试数据目录的 opt-in 评估脚本。
- 不证明：来源未来始终可用、分析普遍正确、所有平台兼容或独立人工验收完成。

## Frozen Acceptance Contract

- Q1 RED：针对真实格式/日期/同源请求边界的失败样本；有效条目、拒绝原因、失败/部分/空结果分别可测试。
- Q2 RED：较新本地快照不会通过现有入口更新；新增后应更新准确项目，保留 saved/triage 时间和不可变分析；无候选/同内容/旧候选/缺失/已取消收藏/非法输入保持正确状态。
- Q2 UI：原生及兼容页按钮、忙碌/结果/错误状态、同 ID 阅读与来源新鲜度同步；键盘激活和窄窗可用。按现有视觉系统实现，不新增审美配置。
- Q3：确定性 fixture 测试重复/目标类型/标签完备性/无效评分；真实执行显式 opt-in，3×2 规划及最多 4 分析有调用台账和输入输出哈希。
- 交付验证：相关 RED/GREEN、`npm run check`、桌面 E2E、受影响原生流程与截图、打包/安装/数据保留、精确路径提交、现有草稿 PR 推送与 CI。完成必需检查后不无故重复全量测试。
