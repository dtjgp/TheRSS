# 来源、收藏快照与质量基线

本轮实现了来源日期与失败状态修复、显式更新收藏快照，并完成 6 次真实规划与 4 次分析尝试。结果不能支持“检索质量已经达标”：复杂约束检索的直接相关项不足，分析样本包含一次超时及一次证据越界。功能、自动检查和本机安装已完成；GitHub 通过现有草稿 PR #49 交付，当前提交的远端状态以该 PR 的检查为准。

## 来源

2026-09-07 的一次 20 个配置源全量检查为 17 fetched、1 partial、2 failed：NCPSD 返回 3 条有年月的记录，拒绝 7 条只有期号的记录；NBER 的 20 条候选没有可接受日期，详情访问拒绝；CNBC 镜像超时。随后仅对 CNBC 改用官方 Top News RSS 定点复测，返回 30 条、0 拒绝、327 ms，保留数字 GUID 和原频道筛选。不能把两次检查合成为一次全量全绿结果。

NCPSD 的月初值只是旧存储中的排序锚点。现在所有相关显示和模型输入保留月份精度，不授予按天的新鲜度奖励；30 天窗口按月区间重叠纳入。只给期号的记录继续拒绝。NBER 403 后停止尚未开始的详情请求，不绕过访问限制；Crossref 候选 404 未采用。错误 HTML、异常 XML、非法日历日期和跨源重定向均有离线回归，失败保留缓存。

## 收藏

原生和 Web Saved 增加 Update saved snapshot。只从同一条目的本地 Discover 历史选择较新快照，并在事务中重查当前来源哈希和候选哈希。收藏时间、初次发现时间、历史检索及分析保持不变；旧分析自然变为过时。取消收藏、候选改变、旧版本和无新快照分别返回明确结果。不联网、不调用模型、无数据库迁移。

## 复核与边界

`scripts/evaluate-discovery.ts` 默认只打印计划，真实检索/分析必须显式 `--live`。新输出目录拒绝覆盖既有 manifest；记录每次调用前的台账、问题/提示版本/来源哈希和文件 SHA-256。报告离线验证原始快照哈希及标签身份；未知标签与 0 分不同。

本轮检索开始后、下一次核心修改前捕获了输入文件哈希，并核对文件修改时间均早于运行开始；分析阶段另有自动输入记录。两阶段来源哈希清单保存在本目录，不能声称本轮运行使用最终提交的全部代码。后续 v3 提示变化发生在分析完成之后。

本机原始快照和调用台账位于 gitignored `test-results/source-quality/baseline-2026-09-07`，公开提交保留规范化报告、来源/输入哈希和辅助标签，不复制全文摘要或账号资料。可用 `npm run evaluate:discovery -- --phase report --out <该目录> --labels <标签文件>` 离线复算。独立人工模板保留 null，真实使用者填写后才可计算其指标。

VoiceOver、新增付费模型 API 和正式 Apple 发行仍按用户决定暂缓；独立人工体验验收继续待填写。没有合并 PR、创建标签或发布软件 Release。
