# 原生滚动增量修复

高频、小幅横向滚动触发布局重绘时，原生事件可能晚于原布局版本到达。旧实现将布局提交期间的展示状态清空，并在主进程、渲染器入口拒绝旧 revision，导致有效滚动增量丢失。严格检查中，输入 39 CSS 像素得到 37、37、37、38、39。

本次用 `scrollRevision` 标明当前有效滚动上下文的首个布局版本，几何刷新期间保留已确认的滚动目标。滚动按有效版本区间处理；点击、键盘和焦点继续精确匹配版本。条目/视图、实际 DOM 根与控件祖先、viewport/zoom、模态或恢复状态变化时，旧滚动上下文失效，须等待新确认。主进程同时检查实时 zoom，避免使用旧缩放比例的增量。没有增加事件队列、重放或原生 ABI 字段。主进程在实时缩放中断时发送受限的 scroll-reset 通知，驱动渲染器重新确认；已观察到的上下文失效不会因弹窗关闭或缩放恢复而被旧 ACK 撤销。

## 验证

- 两条原始 RED 回归分别确认主进程过滤掉旧几何的滚动，以及渲染器在 ACK 前收到 3 像素但移动 0 像素。
- 修复后逻辑和边界测试通过；`npm run check` 通过 66 个文件 / 491 个测试。
- 与缺陷检查相同的公开 AppKit 合成惯性序列连续五次精确得到 39 像素，每次 28 个非零事件全部到达渲染器。
- 桥接专项覆盖率 statements 95.73%、branches 91.20%、functions 94.28%、lines 97.83%，每个文件四项均超过 80%。
- 桌面 6/6 通过，包含三次 39 个一像素事件的完整链路验证；最终安装包的横纵/缩放/惯性矩阵 13/13 通过。安装后原生激活 smoke 通过，app.asar 与原生模块指纹均与测试包一致，见 [verification.json](verification.json)。
- 独立复查补充的弹窗/条目/节点/缩放往返及瞬时缩放恢复问题，经额外 RED→GREEN 和真实 session/hook 联合测试关闭。最终代码审查通过。

临时测试脚本原先仅固定等待 300 ms 后执行准备点击，曾遇到准备点击未应用和目标脱离窗口。准备阶段现等待 fixture 检索完成及已确认的稳定布局，再各执行一次保存和导航；待测滚动包之间仍不等待布局确认。随后严格五次全部通过。临时脚本已压缩归档，运行副本位于测试临时目录，未扩大源码 lint 忽略范围。
