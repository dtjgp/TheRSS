# TheRSS 研究工作流评审

2026-11-06，Europe/Rome。范围：Discover、Sources、Saved、llm-wiki 日扫和 Obsidian 跳转。参见[变更契约](CHANGE_CONTRACT.md)、[界面参考](REFERENCES.md)和[可操作原型](daily-papers.html)。原型数据是确定性样例。

## 产品结论

TheRSS 的 Discover 适合围绕一个研究问题跨源检索。每天上班先看什么，是另一项任务。此前需要在 TheRSS 手动输入问题，或到 llm-wiki 找当天的摘要。Sources 的 arXiv 页面又按 UTC 投稿日取样，无法回答「今天公告了哪些论文」。应把每日精选接到 Discover 的入口，继续让 llm-wiki 管理选题、公告口径、证据和归档。

| 使用任务       | 现状与摩擦                                            | 本轮改进                                                                       |
| -------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------ |
| 开始当天浏览   | Discover 每次从问题出发；arXiv Sources 取样不按公告日 | 在 Discover 中打开 Daily Papers；标明所读公告批次、扫描结果、精选和筛查数量    |
| 判断值不值得读 | 现有检索理由和日扫相关性处于两套入口                  | 直接相关排在邻近相关前；展示日扫的阅读优先级和已有理由                         |
| 回到原文和笔记 | AppKit 读者已有收录状态，Web 读者缺少同等入口         | 两种界面都可读日扫；论文笔记通过规范 ID 验证后跳转；Web 也可查看已有收录及重查 |
| 收藏与归档     | 同一用户会同时使用 TheRSS 收藏和知识库收录            | 保留两者的独立状态；从 Discover 或 Saved 走现有预览、确认和回执流程            |
| 判断来源故障   | 「无结果」容易与当日还未更新混淆                      | 区分缺文件、无公告、部分完成、完整但零精选、读取失败；较早批次明确标日期       |

这里的评分只帮助分配阅读时间。它不代表论文质量、全文已读、结果复现或设备上节能。真实日扫的主题来自 llm-wiki 当前词表与项目规则：例如模型压缩、结构化剪枝和边缘推理。无需在应用里维护第二份个人研究词表。

## 前后端取舍

- **界面：** 用现有列表和详情，日期与结果状态放在列表上方。优先行动是打开已有笔记；同一记录仍可打开官方原文。恢复 Discover 草稿和焦点。参考 [Apple Split Views](https://developer.apple.com/design/human-interface-guidelines/split-views) 的布局和 [Zotero Feeds](https://www.zotero.org/support/feeds) 对阅读与收藏的区分。
- **数据：** TheRSS 的 SQLite 继续保存检索、收藏和分析。llm-wiki 继续保存每日摘要、PDF 和研究笔记。TheRSS 只投影有限字段，不复制全文或笔记库，不改变现有自动化。按日期和 arXiv ID 重新验证跳转，复用 [Obsidian URI](https://obsidian.md/help/uri)。
- **来源：** 明示 Sources 的投稿日期样本和日扫的公告批次。直接取 arXiv 官方 RSS 是独立雷达的候选；它可提供公告日与公告类型。仅在确有独立覆盖需求时增加，避免两套筛选或两套归档任务。[arXiv RSS 规范](https://info.arxiv.org/help/rss_specifications.html)
- **状态与恢复：** 当日不存在时可看过去 14 日内的最近一版；当日已有不完整报告时保留其状态。重查由用户触发。解析或链接核验失败时保留可用的官方原文入口；读者可回到原来的检索。

## 扩展顺序

| 优先级 | 下一步                                                                               | 验收                                                                                        |
| ------ | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| P0     | 在日用安装版完成一篇真实论文的预览、确认、入库和跳转；分别检查日扫和临时检索相关性   | 确认真实 PDF、sidecar、笔记、索引、回执和 Obsidian 目标；安装前后比对用户数据               |
| P1     | 列表收录标记、待检查/已收录筛选，历史每日批次选择；在设置中显示目标 vault 和最近检查 | 未检查不等于未收录；批量查询复用一次有界扫描；低覆盖和来源延迟可见                          |
| P1     | 与 vault 一起定义版本化的每日精选数据契约                                            | 只由现有自动化发布；兼容旧摘要；按日期验证身份、计数、证据和链接；无需解析自由格式段落      |
| P2     | 保存可手动重跑的领域检索；在有需要时添加独立的官方公告查询                           | 验证主题覆盖、重复 ID、new/cross/replacement、ET 公告日和本地时区；在失败时保留可读的前一批 |
| P2     | 连接论文的正式发表版、官方代码与后续动态；仓库和新闻走受控 Inbox 收录                | 显示关联证据；确认前预览写入范围；使用 vault 认可的写入者与审计流程                         |

建议用一周日常使用记录验收：到达短名单的点击数、找到首篇值得打开的耗时、带有效笔记的条数、公告延迟被误读为零结果的次数。当前只验证入口和状态，尚未测量用户耗时变化。

## 验证范围

- 接入测试覆盖文件限额、路径与链接限制、论文身份、日期回退和来源状态。真实 vault 的只读检查确认最新摘要可读取，全部入选笔记的 arXiv ID 匹配，并捕获了摘要和论文笔记的 Obsidian URI。
- 使用固定样例在 Electron 中验证返回 Discover 保留草稿、论文跳转请求、键盘选中和窄窗口。原生界面另有宽屏浅色和窄屏深色截图。独立复核后，过期的原生打开动作按日期和论文 ID 失效。
- 未运行真实论文写入、实体键盘和 VoiceOver 人工验收。未修改 vault、现有日扫或已安装版本。
