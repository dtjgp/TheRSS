## Feature Intake

- 用户目标：在当前全部信息源中选出日常想获取的来源，并长期保留选择。
- 当前证据：Discover 的 Sources 弹出框已支持 22 个来源的任意子集、查找与分组操作。
  `DiscoverScreen.load()` 从上次会话恢复检索来源；尚无独立的默认来源偏好。
  Sources 页目前负责来源目录、状态与单独浏览，不提供默认组合的保存。
- 建议：在 Sources 增加“我的信息源”管理入口，保存默认组合；Discover 保留单次调整。
- 替代方案：仅改善现有单次选择（成本低，仍不能独立管理默认组合）；全局禁止来源访问
  （会影响单独浏览、刷新和历史重试，超出本方案）；多个命名组合（首版延后）。
- 产品适配：加强用户主动 Discover，不新增自动订阅、后台获取或数据清理。
- 成本：实现中等，涉及共享偏好、两条展示路径、初始化和异步状态；无新增运行服务或付费调用。
- 边界：偏好写入现有本地 SQLite 所属服务；新增受校验的读取/保存接口。具体表结构和向后回退
  在用户批准后由 Engineer 冻结。不能把它放入仅原生的布局偏好文件，造成两条路径不一致。
- 原型阶段停止条件已满足，用户已确认。实施停止条件：获批功能完成、相关检查结果明确、
  Manager 独立审查与原生交互复核完成；未授权的安装和发布不作为本轮动作。

## Capability Contract

### 核心操作

1. 进入 Sources，顶部显示“我的信息源 · N/22”，打开“默认检索来源”原生 sheet。
2. sheet 按当前五个分组展示全部 22 个来源。每项显示复选框、真实名称和现有用途说明。
   搜索只查找来源名称、用途和分组，不获取远程内容。支持“仅看已选”。
3. 批量动作明确为“选择当前显示”“取消当前显示”，只作用于当前查找和筛选结果。
   分组标题显示已选数/总数，首版不再增加语义重叠的组选择按钮。
4. 底部显示“已选 N/22”，提供“取消”“保存默认来源”。恢复全部只修改未保存的勾选。
   改动前后的选中数量真实计算，不展示虚构健康度或抓取结果。
5. 保存成功后显示“默认来源已保存，下次新搜索使用”；保存本身不启动检索。
6. Discover 将 Sources 按钮明确为“本次来源 · N/22”。打开相同选择器，但标题为“本次检索来源”，
   按钮为“应用到本次搜索”。另有“使用默认组合”；临时选择不写回默认组合。
7. 仍需用户点击 Search，才按本次明确选中的来源执行检索。

### 生效规则

| 操作/状态         | 默认组合       | 下一次搜索草稿                                                     | 已有结果与任务                                     |
| ----------------- | -------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| Sources 保存默认  | 更新并持久保留 | 未临时调整且无运行中任务时同步；否则保留用户草稿并提示使用默认组合 | 不变                                               |
| Discover 临时调整 | 不变           | 应用新组合                                                         | 不变，提示“来源已调整，搜索后生效”                 |
| 恢复默认组合      | 不变           | 回到已保存组合                                                     | 不变                                               |
| 重启应用          | 读取已保存组合 | 用默认组合初始化，不再被旧会话覆盖                                 | 旧会话仍按原来源展示，数量独立标注                 |
| 点击 Search       | 不变           | 使用当前组合                                                       | 新会话记录本次实际来源                             |
| 重试旧会话        | 不变           | 不覆盖草稿                                                         | 只重试该会话原先的失败/部分/取消来源，仍使用原计划 |

临时组合在当前搜索草稿中保持到用户重新调整、选择“使用默认组合”或重启；
完成搜索时不自动跳回其他组合，以免在展示结果时突然改动控件。

首次启用时，优先把上次成功保存会话的来源组合作为初始默认；没有历史时全部 22 个选中。
有独立默认偏好后，不再用历史会话覆盖它。来源选择为空时允许继续编辑，但保存/应用不可用，
就近显示“至少选择一个来源”。不得偷偷回退到全部来源。

### 语义与失败边界

- “我的信息源”表示 Discover 的默认检索组合。Sources 的单独浏览和明确刷新仍沿用既有操作，
  不是系统级网络访问开关；Saved、旧结果与其来源标签不删除、不隐藏。
- Daily Papers 继续读取已有 llm-wiki 日报，不受这 22 个适配器的默认组合控制。
- 检索进行中不改变该任务来源；允许保存未来偏好时也必须提示其生效范围。
- 某来源失败不自动取消选中，继续保留真实失败、部分、无结果和最后检查时间的区别。
- 保存失败保留勾选草稿并给出重试；偏好读取失败显示明确提示，不静默把选择改为全选。
- 来源目录未来变更时，新来源不自动加入已保存组合。旧 ID 已不受支持时提示重新检查；
  有效集合变为 0 时阻止检索，不能替用户决定新来源。
- 暂不增加来源、URL 订阅、自定义分组、多个命名组合、定时刷新或“只看已选”的历史结果过滤。

## Uncertainty Reducer

- 选择器原型：`prototype.html`，来源名称和分组由当前项目目录提取，全部 22 个均来自现有注册表。
- HTML 用浏览器独立 localStorage 保存演示默认组合，模拟单次来源和旧会话；不连接应用数据库、
  vault、模型或外部来源。“演示搜索”只更新原型中的范围摘要，没有实际结果获取。
- 原型用于确认默认/临时两层选择、批量操作、取消、空选择和重启；不证明 AppKit、IPC、
  SQLite、抓取质量、可访问性或真实任务隔离已经实现。
